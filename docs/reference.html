1. Vue d'ensemble du Projet

Le projet AlgorithmCompiler a pour vocation de fournir un outillage pédagogique et technique de niveau professionnel pour l'enseignement de l'algorithmique. Conçu en C++20 avec une tolérance stricte aux pannes (testé via un harnais de fuzzing automatisé), il permet à la fois d'exécuter pas à pas les algorithmes avec des diagnostics clairs, de visualiser leur compilation en bytecode machine virtuel, et de les exporter vers du code Python idiomatique.

💡 Conformité aux programmes officiels : Prend en charge la syntaxe et les conventions des sections Mathématiques, Sciences Expérimentales, Sciences de l'Informatique, Technique et Économie-Gestion.

2. Utilisation en Ligne de Commande (CLI `algo.exe`)

L'exécutable autonome algo.exe (ou ./algo sous Linux/macOS) offre une panoplie d'options pour l'exécution, le contrôle sémantique et la transpilation :

algo.exe <fichier.alg> [OPTIONS]
algo.exe [OPTIONS]
Option Paramètres Description détaillée
-h, --help — Affiche le manuel complet de la ligne de commande et quitte.
-v, --version — Affiche la version (v1.5.1), le compilateur hôte, la plateforme et le standard C++20.
--check — Exécute exclusivement l'analyse lexicale, syntaxique et sémantique (types, portées, arités) sans lancer l'exécution.
--vm — Active l'exécution via la Machine Virtuelle à Bytecode (activé par défaut, ultra-rapide).
--ast — Force l'exécution directe sur l'Arbre Syntaxique Abstrait via le patron Visiteur.
--compare — Exécute le fichier avec l'AST puis avec la VM et affiche la comparaison précise des durées.
--time, --bench — Mesure et affiche à la fin le temps d'exécution exact en millisecondes.
--dump-bytecode — Désassemble le bytecode compilé (opcodes, pile, constantes) sans exécuter.
--to-python, --py [fichier.py] Transpile l'algorithme vers Python 3 propre. Écrit dans le fichier cible si spécifié, sinon sur la sortie console.
--max-iter <N> Seuil de prévention des boucles infinies (Défaut : 1 000 000).
--timeout <ms> Délai d'exécution maximum accordé en millisecondes (Défaut : 50 000 ms).
--seed <N> Fixe la graine initiale pseudo-aléatoire (reproductibilité des fonctions Alea).

3. Structure d'un Algorithme

Un programme algorithmique standard se compose d'un nom, de sous-programmes éventuels, du bloc principal Début ... Fin, et des tables déclaratives officielles :

Algorithme Tri_Tableau
Début
    Remplir(T, N)
    Trier(T, N)
    Afficher(T, N)
Fin

TDO
Objet : Type/Nature
T : Tableau de 50 entier
N : entier
Remplir, Trier, Afficher : Procédure
Tables déclaratives reconnues :
  • TDO / TDOG : Tableau de Déclaration des Objets Globaux (variables, constantes, procédures).
  • TDNT : Tableau de Déclaration des Nouveaux Types (enregistrements, alias de tableaux, énumérés).
  • TDOL : Tableau de Déclaration des Objets Locaux (spécifique au sous-programme qui le précède).
  • Const : Déclarations de constantes globales directes.
  • Importer : Inclusion modulaire de bibliothèques tierces (ex: Importer "math_utils.alg").

6. Instructions Supportées par algo.exe

6.1 Instruction d'Affectation (`←`, `<-`, `:=`)

Assigne la valeur d'une expression à une variable simple, un indice de tableau, une matrice ou un champ d'enregistrement.

// Variables scalaires
compteur ← compteur + 1
// Tableaux et Matrices
notes[i] ← 17.5
grille[lig, col] ← 0
// Enregistrements (directs ou imbriqués)
etudiant.nom ← "Amira"
etudiant.adresse.ville ← "Tunis"

6.2 Entrées / Sorties (`Ecrire`, `Ecrire_NL`, `Lire`)

Affichage à l'écran et saisie interactive au clavier avec conversion automatique vers le type attendu :

// Affichage standard
Ecrire("Moyenne générale :", moy)

// Affichage avec séparateur personnalisé et sans saut de ligne
Ecrire("Notes :", n1, n2, n3, sep = " | ", fin = " ")

// Affichage avec saut de ligne garanti
Ecrire_NL("Traitement terminé avec succès.")

// Saisie clavier utilisateur
Ecrire("Donner le rayon du cercle : ")
Lire(rayon)

6.3 Structure Conditionnelle (`Si ... Alors ... Sinon Si ... Sinon ... Fin Si`)

Si note >= 16 Alors
    mention ← "Très Bien"
Sinon Si note >= 14 Alors
    mention ← "Bien"
Sinon Si note >= 12 Alors
    mention ← "Assez Bien"
Sinon Si note >= 10 Alors
    mention ← "Passable"
Sinon
    mention ← "Non admis"
Fin Si

6.4 Aiguillage Multiple (`Selon ... Cas ... Autrement ... Fin Selon`)

Selon code_choix Faire
    Cas 1 :
        Ecrire("Opération d'ajout")
    Cas 2, 3 :
        Ecrire("Opération de consultation ou modification")
    Cas 4 .. 9 :
        Ecrire("Opération d'administration")
    Autrement :
        Ecrire("Code opération non reconnu !")
Fin Selon

6.5 Boucles Récurrentes (`Pour`, `Tant Que`, `Répéter`)

1. Boucle Pour (croissante, décroissante, avec pas) :

Pour i de 0 à n - 1 Faire
    somme ← somme + t[i]
Fin Pour

Pour k de 10 à 0 Pas -2 Faire
    Ecrire("k =", k)
Fin Pour

2. Boucle Tant Que (précondition) :

Tant Que (x > 0) Faire
    x ← x div 10
    nb_chiffres ← nb_chiffres + 1
Fin Tant Que

3. Boucle Répéter ... Jusqu'à (postcondition & validation) :

Répéter
    Ecrire("Donner la taille du tableau (3 .. 30) : ")
    Lire(taille)
Jusqu'à 3 ≤ taille ≤ 30

6.6 Procédures & Fonctions (`@param` par référence, `Retourner`)

// Procédure avec passage par référence '@'
Procédure Inverser_Tableau(@t : TabNotes; n : entier)
Début
    Pour i de 0 à (n div 2) - 1 Faire
        tmp ← t[i]
        t[i] ← t[n - 1 - i]
        t[n - 1 - i] ← tmp
    Fin Pour
Fin

// Fonction avec valeur de retour
Fonction PGCD(a : entier; b : entier) : entier
Début
    Tant Que b ≠ 0 Faire
        r ← a mod b
        a ← b
        b ← r
    Fin Tant Que
    Retourner a
Fin

6.7 Manipulation de Fichiers (`Ouvrir`, `Lire_Ligne`, `Aller_A`, `Fermer`)

// 1. Écriture dans un fichier texte ("w" = écriture, "a" = ajout, "r" = lecture)
Ouvrir(f, "resultats.txt", "w")
Ecrire(f, "Algorithme v1.5.1")
Fermer(f)

// 2. Lecture ligne à ligne jusqu'à la fin de fichier
Ouvrir(f, "resultats.txt", "r")
Tant Que Non Fin_Fichier(f) Faire
    Lire_Ligne(f, ligne)
    Ecrire("Ligne :", ligne)
Fin Tant Que
Fermer(f)

6.8 Gestion Dynamique de Mémoire (`Allouer`, `Liberer`, `NIL`)

Allocation dynamique sur le tas, passage de références, piles, files, listes chaînées et arbres :

// 1. Déclaration et initialisation
p ← NIL

// 2. Allocation dynamique sur le tas
Allouer(p)
p^.valeur ← 42
p^.suivant ← NIL

// 3. Sucre syntaxique d'accès direct au champ (p.champ <=> p^.champ)
p.valeur ← 100

// 4. Libération de la mémoire (p redevient automatiquement NIL)
Liberer(p)

7. Bibliothèque Standard des Fonctions Prédéfinies

Catégorie Fonction Description & Comportement

Ent(x) / Arrondi(x) Partie entière ($\lfloor x \rfloor$) et arrondi au plus proche.

8. Diagnostics Sémantiques & Messages Rust-style

L'analyseur sémantique d'AlgorithmCompiler fournit des messages précis avec numéros de lignes, colonnes, soulignement visuel du problème et proposition de correction la plus probable par distance de Levenshtein :

Erreur sémantique (ligne 4, colonne 10) :
      Ecrire(totla + 1)
             ^~~~~
La variable 'totla' non définie (objet non déclaré dans le TDO/TDOL).
Suggestion : Vouliez-vous dire 'total' ? (ligne 4)

9. Transpilateur Python 3 (`--to-python`)

La commande algo.exe source.alg --to-python out.py génère un fichier Python prêt à l'emploi :

  • Importation sélective automatique (from math import sqrt, exp).
  • Représentation des tableaux et matrices par NumPy (np.zeros).
  • Respect absolu de l'interdiction pédagogique du mot-clé break (transpilation propre des boucles Répéter sans while True).

10. Machine Virtuelle à Bytecode (`--vm`, `--dump-bytecode`)

Le moteur VM intègre un optimiseur peephole, le pliage de constantes à la compilation et des chemins d'exécution rapides dédiés aux tableaux et aux calculs entiers 64 bits. Vous pouvez inspecter le bytecode généré en passant l'option --dump-bytecode :
