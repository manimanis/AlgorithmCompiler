1. Vue d'ensemble du Projet

Le projet AlgorithmCompiler a pour vocation de fournir un outillage pédagogique et technique de niveau professionnel pour l'enseignement de l'algorithmique. Conçu en C++20 avec une tolérance stricte aux pannes (testé via un harnais de fuzzing automatisé), il permet à la fois d'exécuter pas à pas les algorithmes avec des diagnostics clairs, de visualiser leur compilation en bytecode machine virtuel, et de les exporter vers du code Python idiomatique.

💡 Conformité aux programmes officiels : Prend en charge la syntaxe et les conventions des sections Mathématiques, Sciences Expérimentales, Sciences de l'Informatique, Technique et Économie-Gestion.

3. Structure d'un Algorithme

Un programme algorithmique standard se compose d'un nom, de sous-programmes éventuels, du bloc principal Début ... Fin, et des tables déclaratives officielles :

Algorithme Tri_Tableau
Début
    Remplir(T, N)
    Trier(T, N)
    Afficher(T, N)
Fin

TDO
Objet : Type/Nature
T : Tableau de 50 entier
N : entier
Remplir, Trier, Afficher : Procédure
Tables déclaratives reconnues :
  • TDNT : Tableau de Déclaration des Nouveaux Types (enregistrements, tableaux personnalisés, types énumérés et sous-intervalles).
  • TDO / TDOG : Tableau de Déclaration des Objets Globaux (variables, constantes et procédures globales).
  • TDOL : Tableau de Déclaration des Objets Locaux (associé à chaque procédure ou fonction).
  • Importer : Inclusion modulaire de fichiers ou bibliothèques externes (ex: Importer Racine Depuis "math_utils.alg").

6. Instructions Supportées par algo.exe

6.1 Instruction d'Affectation (`←`, `<-`, `:=`)

Assigne la valeur d'une expression à une variable simple, un indice de tableau, une matrice ou un champ d'enregistrement.

// Variables scalaires
compteur ← compteur + 1
// Tableaux et Matrices
notes[i] ← 17.5
grille[lig, col] ← 0
// Enregistrements (directs ou imbriqués)
etudiant.nom ← "Amira"
etudiant.adresse.ville ← "Tunis"

6.2 Entrées / Sorties (`Ecrire`, `Ecrire_NL`, `Lire`)

Affichage à l'écran et saisie interactive au clavier avec conversion automatique vers le type attendu :

// Affichage standard
Ecrire("Moyenne générale :", moy)

// Affichage avec séparateur personnalisé et sans saut de ligne
Ecrire("Notes :", n1, n2, n3, sep = " | ", fin = " ")

// Affichage avec saut de ligne garanti
Ecrire_NL("Traitement terminé avec succès.")

// Saisie clavier utilisateur
Ecrire("Donner le rayon du cercle : ")
Lire(rayon)

6.3 Structure Conditionnelle (`Si ... Alors ... Sinon Si ... Sinon ... Fin Si`)

Si note >= 16 Alors
    mention ← "Très Bien"
Sinon Si note >= 14 Alors
    mention ← "Bien"
Sinon Si note >= 12 Alors
    mention ← "Assez Bien"
Sinon Si note >= 10 Alors
    mention ← "Passable"
Sinon
    mention ← "Non admis"
Fin Si

6.4 Aiguillage Multiple (`Selon ... Cas ... Sinon ... Fin Selon`)

Selon code_choix Faire
    1 :
        Ecrire("Opération d'ajout")
    2, 3 :
        Ecrire("Opération de consultation ou modification")
    4 .. 9 :
        Ecrire("Opération d'administration")
    Sinon
        Ecrire("Code opération non reconnu !")
Fin Selon

6.5 Boucles Récurrentes (`Pour`, `Tant Que`, `Répéter`)

1. Boucle Pour (scalaires : entier, caractère ou booléen, avec pas optionnel) :

// Scalaire entier (croissant par défaut ou décroissant avec pas)
Pour i de 0 à n - 1 Faire
    somme ← somme + t[i]
Fin Pour

Pour k de 10 à 0 Pas -2 Faire
    Ecrire("k =", k)
Fin Pour

// Scalaire caractère (parcours alphabétique)
Pour c de "A" à "Z" Faire
    Ecrire(c)
Fin Pour

// Scalaire booléen (parcours de vérité)
Pour b de Faux à Vrai Faire
    Ecrire(non b)
Fin Pour

2. Boucle Tant Que (précondition) :

Tant Que (x > 0) Faire
    x ← x div 10
    nb_chiffres ← nb_chiffres + 1
Fin Tant Que

3. Boucle Répéter ... Jusqu'à (postcondition & validation) :

Répéter
    Ecrire("Donner la taille du tableau (3 .. 30) : ")
    Lire(taille)
Jusqu'à 3 ≤ taille ≤ 30

6.6 Procédures & Fonctions (`@param` par adresse, `Retourner`)

// Procédure avec passage par adresse '@'
Procédure Inverser_Tableau(@t : TabNotes; n : entier)
Début
    Pour i de 0 à (n div 2) - 1 Faire
        tmp ← t[i]
        t[i] ← t[n - 1 - i]
        t[n - 1 - i] ← tmp
    Fin Pour
Fin

// Fonction avec valeur de retour
Fonction PGCD(a : entier; b : entier) : entier
Début
    Tant Que b ≠ 0 Faire
        r ← a mod b
        a ← b
        b ← r
    Fin Tant Que
    Retourner a
Fin

6.7 Manipulation de Fichiers (`Ouvrir`, `Lire_Ligne`, `Aller_A`, `Fermer`)

// 1. Écriture dans un fichier texte ("w" = écriture, "a" = ajout, "r" = lecture)
Ouvrir(f, "resultats.txt", "w")
Ecrire(f, "Algorithme v1.8.1")
Fermer(f)

// 2. Lecture ligne à ligne jusqu'à la fin de fichier
Ouvrir(f, "resultats.txt", "r")
Tant Que Non Fin_Fichier(f) Faire
    Lire_Ligne(f, ligne)
    Ecrire("Ligne :", ligne)
Fin Tant Que
Fermer(f)

6.8 Gestion Dynamique de Mémoire (`Allouer`, `Liberer`, `NIL`)

Allocation dynamique sur le tas, passage de références, piles, files, listes chaînées et arbres :

// 1. Déclaration et initialisation
p ← NIL

// 2. Allocation dynamique sur le tas
Allouer(p)
p^.valeur ← 42
p^.suivant ← NIL

// 3. Sucre syntaxique d'accès direct au champ (p.champ <=> p^.champ)
p.valeur ← 100

// 4. Libération de la mémoire (p redevient automatiquement NIL)
Liberer(p)

8. Diagnostics Sémantiques & Messages Rust-style

L'analyseur sémantique (algo.exe --check) valide l'intégralité du code avant toute exécution et signale :

  • Les variables, procédures ou fonctions non déclarées dans le TDO/TDOL/TDNT.
  • Les incohérences de types (affectation d'une chaîne dans un entier, condition non booléenne dans un Si ou Tant Que).
  • Les violations d'arité (nombre d'arguments incorrect lors de l'appel).
  • Les passages d'expressions constantes ou de littéraux à des paramètres passés par adresse (@param).
  • Les accès à des champs inexistants dans des enregistrements.

Les messages d'erreur fournissent le numéro de ligne, la colonne, le soulignement visuel du problème (^~~~) et la proposition de correction la plus probable par distance de Levenshtein :

Erreur sémantique (ligne 4, colonne 10) :
      Ecrire(totla + 1)
             ^~~~~
La variable 'totla' non définie (objet non déclaré dans le TDO/TDOL).
Suggestion : Vouliez-vous dire 'total' ? (ligne 4)

10. Machine Virtuelle, Bytecode Binaire & Exécutables Autonomes (`--vm`, `--compile-bc`, `--build-exe`)

La Machine Virtuelle à Bytecode d'AlgorithmCompiler offre des gains de performance de plus de 75x par rapport à l'évaluation pure d'AST :

  • Fast-paths 1D pour tableaux : Opcodes spécialisés (OP_ARRAY_GET_GLOBAL, OP_ARRAY_SET_GLOBAL, OP_ARRAY_GET_LOCAL, OP_ARRAY_SET_LOCAL) éliminant toute copie inutile.
  • Fast-paths arithmétiques : Traitement direct inliné des opérandes entiers 64-bit pour +, -, *, div, mod, <.
  • Gestion des pointeurs et tas VM : Opcodes spécialisés (OP_ALLOC_PTR, OP_FREE_PTR, OP_DEREF, OP_REF_DEREF) pour l'allocation sur le tas, le déréférencement sécurisé et la détection d'accès NIL.
  • Optimiseur Peephole : Élimination des instructions inutiles et chaînage direct des sauts conditionnels (OP_JUMP_IF_FALSE).
  • Pliage de constantes (Constant Folding) : Évaluation au moment de la compilation des sous-expressions statiques (ex. 2 * 3.14 * 10).

10.3 Génération d'Exécutables Autonomes Indépendants (`.exe`)

Vous pouvez générer un exécutable .exe Windows 100% autonome et sans dépendances à partir de n'importe quel code source .alg ou fichier bytecode .algb :

algo.exe mon_programme.alg --build-exe mon_programme.exe
# ou syntaxe rapide :
algo.exe mon_programme.alg -b
Fonctionnement technique de l'exécutable autonome :

• Patron d'overlay PE (PE Overlay Pattern) : le bytecode sérialisé est encapsulé directement à la fin du binaire avec un marqueur ALGBEXEC et sa taille en 64 bits.
• Zéro dépendance de compilation : aucune chaîne d'outils externe (GCC, MinGW, Clang) n'est requise lors de la génération.
• Distribution immédiate : l'exécutable généré est statiquement lié (-static -static-libgcc -static-libstdc++) et ne dépend d'aucune DLL tierce. Il fonctionne sur n'importe quel PC Windows par double-clic ou en console.

11. Exemples de Structures Dynamiques

11.1 Pile Dynamique (LIFO - Dernier Entré, Premier Sorti)

Algorithme TestPile
TDNT
Element = Enregistrement
    valeur : entier
    suivant : ^Element
Fin
Pile = ^Element

Procédure Empiler(@p : Pile; val : entier)
Début
    Allouer(nouveau)
    nouveau.valeur ← val
    nouveau.suivant ← p
    p ← nouveau
Fin
TDOL
nouveau : Pile

Procédure Depiler(@p : Pile; @val : entier)
Début
    Si p ≠ NIL Alors
        val ← p.valeur
        temp ← p
        p ← p.suivant
        Liberer(temp)
    Fin Si
Fin
TDOL
temp : Pile

Début
    sommet ← NIL
    Empiler(sommet, 10)
    Empiler(sommet, 20)
    Empiler(sommet, 30)

    Tant Que sommet ≠ NIL Faire
        Depiler(sommet, v)
        Ecrire("Dépilé :", v)
    Fin Tant Que
Fin
TDO
sommet : Pile
v : entier

11.2 File Dynamique (FIFO - Premier Entré, Premier Sorti)

Algorithme TestFile
TDNT
Noeud = Enregistrement
    donnee : entier
    suivant : ^Noeud
Fin
File = Enregistrement
    tete : ^Noeud
    queue : ^Noeud
Fin

Procédure Enfiler(@f : File; val : entier)
Début
    Allouer(nouveau)
    nouveau.donnee ← val
    nouveau.suivant ← NIL
    Si f.tete = NIL Alors
        f.tete ← nouveau
        f.queue ← nouveau
    Sinon
        f.queue.suivant ← nouveau
        f.queue ← nouveau
    Fin Si
Fin
TDOL
nouveau : ^Noeud

Début
    f.tete ← NIL
    f.queue ← NIL
    Enfiler(f, 100)
    Enfiler(f, 200)
    Ecrire("Tête :", f.tete.donnee, "Queue :", f.queue.donnee)
Fin
TDO
f : File

11.3 Arbre Binaire de Recherche (ABR)

Algorithme TestArbre
TDNT
NoeudArbre = Enregistrement
    valeur : entier
    gauche : ^NoeudArbre
    droite : ^NoeudArbre
Fin
Arbre = ^NoeudArbre

Procédure Inserer(@racine : Arbre; val : entier)
Début
    Si racine = NIL Alors
        Allouer(racine)
        racine.valeur ← val
        racine.gauche ← NIL
        racine.droite ← NIL
    Sinon Si val < racine.valeur Alors
        Inserer(racine.gauche, val)
    Sinon
        Inserer(racine.droite, val)
    Fin Si
Fin

Procédure AfficherInfixe(racine : Arbre)
Début
    Si racine ≠ NIL Alors
        AfficherInfixe(racine.gauche)
        Ecrire(racine.valeur)
        AfficherInfixe(racine.droite)
    Fin Si
Fin

Début
    racine ← NIL
    Inserer(racine, 50)
    Inserer(racine, 30)
    Inserer(racine, 70)
    Ecrire("Parcours Infixe :")
    AfficherInfixe(racine)
Fin
TDO
racine : Arbre

algo.exe mon_programme.alg -f diagramme.mmd

Génère une page web autonome complète contenant :

  • Une barre d'outils interactive : Zoom avant (+), Zoom arrière (-), Réinitialisation (Reset), Plein écran, et Export SVG vectoriel immédiat.
  • La navigation panoramique à la souris (Pan & Zoom via svg-pan-zoom).
  • Aucun serveur web requis : double-cliquez simplement sur le fichier .html pour l'ouvrir dans n'importe quel navigateur !

13. Détection de Fuites de Mémoire pour les Pointeurs (`--leak-check`)

Lors de la manipulation de structures dynamiques (listes chaînées, piles, files, arbres, graphes), la gestion rigoureuse de la mémoire est primordiale pour l'apprentissage. AlgorithmCompiler intègre un vérificateur de fuites de mémoire (Memory Leak Checker) activable via le drapeau --leak-check :

algo.exe pile_dynamique.alg --leak-check
Fonctionnement du traqueur :

1. Chaque appel à Allouer(p) enregistre l'allocation : identifiant du bloc, adresse virtuelle, type d'objet, taille mémoire, numéro de ligne et colonne source.
2. Chaque appel à Liberer(p) désalloue l'objet et retire son entrée du registre.
3. À la fin du programme (ou en cas d'erreur fatale), le compilateur dresse un rapport d'audit exhaustif.

✓ Aucune fuite : Affiche l'indicateur de réussite vert :
[SUCCÈS] Vérification mémoire : Aucune fuite détectée (tous les blocs alloués ont été correctement libérés).
⚠️ Fuites détectées : Énumère chaque bloc mémoire non libéré avec son adresse virtuelle et son emplacement source d'allocation pour faciliter la correction par l'élève.

Fonctionne de manière transparente aussi bien avec le moteur d'interprétation AST (--ast) qu'avec la Machine Virtuelle à Bytecode (--vm).

14. Trace d'Exécution Pédagogique (Runtime Stack Trace)

En cas d'erreur survenant lors de l'exécution (division entière ou réelle par zéro, modulo par zéro, débordement d'indice de tableau, déréférencement d'un pointeur NIL, ou récursion infinie dépassant la limite d'appels), AlgorithmCompiler génère une trace de pile d'appels (Call Stack) hautement visuelle et pédagogique :

==============================================================================
 ERREUR D'EXÉCUTION : Débordement d'indice de tableau : indice 5 hors des bornes [0..4] (ligne 14)
==============================================================================
 -> Ligne 14 :
        t[i] ← t[i + 1]
        ^~~~

Trace des appels (Call Stack) :
  #0  Procédure Decaler_Gauche(t, 4) à la ligne 14
  #1  Procédure Supprimer_Element(t, 2) à la ligne 28
  #2  Algorithme Principal Gestion_Tableau à la ligne 45
==============================================================================
Caractéristiques de la trace :

• Pointeur visuel sous le jeton responsable (^~~~).
• Numérotation inversée des cadres d'appels (#0 = lieu de l'exception, #1 = appelant direct, ..., #N = bloc principal).
• Affichage des noms des procédures et fonctions et de leurs arguments actuels.

15. Optimisations Bytecode & Élimination du Code Mort (DCE)

Le compilateur de bytecode (BytecodeCompiler) intègre une passe d'optimisation statique active par défaut :

  • Élimination du code mort après Retourner (Dead Code Elimination) : Toutes les instructions situées après un Retourner inconditionnel au sein d'un même bloc de sous-programme sont élaguées dès la compilation et ne génèrent aucun opcode bytecode.
  • Élagage des branches conditionnelles constantes : Les structures Si Vrai Alors ... ou Si Faux Alors ... sont simplifiées à la compilation, éliminant les sauts conditionnels superflus.
  • Pliage de constantes (Constant Folding) : Les expressions arithmétiques ou logiques entre littéraux constants (ex. 2 + 3 * 4) sont pré-calculées à la compilation.

Pour inspecter les effets de ces optimisations sur vos algorithmes, utilisez :

algo.exe mon_programme.alg --dump-bytecode

16. Studio Web & WebAssembly (Wasm)

AlgorithmCompiler peut être compilé vers le Web sous forme de module binaire WebAssembly (Wasm) grâce à Emscripten SDK (emsdk). Une application web moderne prête à l'emploi est incluse dans le dossier web/ :

16.1 Compilation WebAssembly

# Sous Windows (script batch avec auto-détection intelligente de C:\emsdk) :
build_wasm.bat

# Sous Linux / macOS :
./build_wasm.sh
# ou avec le Makefile (Linux, macOS, WSL) :
make wasm

Cette commande produit :

  • web/algo.wasm : Le binaire WebAssembly optimisé en -O3 (~950 Ko).
  • web/algo.js : Le module JavaScript d'initialisation et de liaison des fonctions exportées (~60 Ko).

16.2 Fonctions Exportées de l'API C / WebAssembly

Fonction C exportée Rôle
algo_run(src, stdin, maxIter, timeoutMs) Exécute l'algorithme sur la Bytecode VM dans le navigateur et renvoie la sortie console.
algo_check(src) Lance l'analyse sémantique statique et renvoie les diagnostics au format JSON.
algo_to_python(src) Transpile le code en Python 3 directement dans le client web.
algo_flowchart(src, mode) Génère l'organigramme Mermaid ou HTML pour visualisation immédiate.
algo_signatures(src) Extrait les signatures des sous-programmes et infère les tables TDO/TDNT.
algo_version() Retourne la chaîne d'information complète de version.

16.3 Tester le Studio Web en Local

Lancez simplement un serveur HTTP statique dans le dossier web/ :

# Avec Python :
python -m http.server -d web 8080

# Ou avec Node.js :
npx serve web

Puis accédez à http://localhost:8080 dans votre navigateur.

17. Gestion Universelle des Commentaires

AlgorithmCompiler intègre un moteur de traitement lexical et syntaxique des commentaires entièrement résistant :

  • Commentaires de fin de ligne : // mon commentaire
  • Commentaires multi-lignes : /* commentaire sur plusieurs lignes */

Les commentaires sont filtrés de manière transparente dès l'entrée dans l'analyseur syntaxique (Parser), ce qui garantit qu'un commentaire ne provoque jamais d'erreur de syntaxe, quel que soit son emplacement :

  • Au milieu d'une boucle Répéter ... Jusqu'à.
  • Entre les mots-clés Sinon et Si (Sinon /* comment */ Si).
  • Au sein d'une liste de paramètres ou d'arguments.
  • Dans les tables de déclarations (TDO, TDOL, TDNT).
